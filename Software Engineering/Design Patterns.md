*Each pattern describes a problem which occurs over and over again in our environment, and then describes the core of the solution to that problem, in such a way that you can use this solution a million times over, without ever doing it the same way twice* - Christopher Alexander

A design pattern has four essential elements:
1. <mark style="background: #D2B3FFA6;">Pattern Name</mark>
	The handle used to describe the a design problem. Naming the pattern enables developers to discuss the designs and communicate properties such as trade offs and benefits.
2. <mark style="background: #D2B3FFA6;">Problem</mark>
	Describes when to apply the pattern. It explains the problem and its context. Can also include a list of conditions that must be met before it makes sense to apply the pattern.
3. <mark style="background: #D2B3FFA6;">Solution</mark>
	Describes the elements that make up the design, the relationship, responsibilities, and collaborations. The solution does not describe a particular concrete design or implementation. Instead, it provides an abstract description of a design problem and how a general arragenemtn of elements solves it.
4. <mark style="background: #D2B3FFA6;">Consequences</mark>
	The results and trade-offs of applying the pattern. Helps in evaluating design alternatives and understanding costs and benefits of applying the pattern. Often concerns space and time trade-offs. They may also address language and implementation issues as well as the impact on a system's flexibility, extensibility, or portability.
# Creational Patterns

Creational design patterns <mark style="background: #FFF3A3A6;">abstract the instantiation process</mark>. They help make a system independent of how its objects are created and represented. A class creational pattern uses inheritance to vary the class thats instantiated, vs an object creational pattern will delegate instantiation to another object.
